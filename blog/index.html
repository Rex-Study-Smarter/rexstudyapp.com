Rex

I built an AI-tutored whiteboard, and kept the safety layer on my own machine

How Rex got built with GLM driving a real browser — and why its moderation is a 421M-parameter classifier that never touches a network.

What Rex is

Rex is an AI-tutored digital whiteboard for iOS and macOS. Students draw, import files, and drop interactive widgets onto an infinite board: graphing charts, 3D science scenes you can walk through (every system of the human body, all the way down to skin cross-sections), language-learning scenes, notes, timers, and a built-in browser. An AI tutor walks through the material with them — out loud. A recent build added podcast mode: Rex and a co-host discuss your notes as a two-host conversation, played over the lecture's own visuals.

It ships as one app, solo-developed, and it's on the App Store now.

Building it with GLM and a real browser

I paired with GLM (via ZCode) through the whole project, and the part that changed how I work wasn't code generation — it was browser automation.

Rex has its own browser widget, which means the hardest bugs live inside a web view: downloads that silently fail because the link opens a new tab, YouTube playback fighting the app for controls, ads that break the player. These are exactly the bugs that are miserable to reproduce by hand. So the agent drove a real browser against the app and fixed them where they lived:

  • downloads now work when the target link opens a new tab
  • YouTube ad-skipping got smoothed out (fewer jarring skips, better seeking)
  • Chrome-style picture-in-picture, instead of a half-custom hack
  • research-connection tiles get named after the page they loaded

The git history reads like a log of agent-driven browser sessions. One commit is "Add Laya"; several others are just the browser behaving like a native citizen. Agentic tooling didn't just write the code — it operated the product.

The moderation problem, and why I didn't buy my way out of it

Every app with an AI feature has a moderation problem. The default answer is a content-moderation API: pay per call, require network, and send your users' text — students' notes, in my case — to a third party for screening.

I didn't want that, for three reasons: cost that scales with usage, a network dependency in the critical path of an offline-capable app, and shipping user text off the device to have it judged.

So I built Laya. It's a 421M-parameter ModernBERT classifier that runs entirely on the machine. Four modes:

  • guard — screen a prompt before acting on it (jailbreaks, injection, leaked secrets, harm)
  • scan — screen untrusted content before reading it (planted instructions, hidden HTML, encoded payloads)
  • moderate — screen text before it goes public (toxicity, harassment, spam)
  • ask — custom yes/no or category questions over many texts

No API key, no network, no cost per call. Nothing you pass it leaves the machine. Cold start is about 15 seconds; after that, roughly a second per call on a warm server shared by every agent on the machine.

"Measured, not assumed"

The sentence I hold myself to with Laya is that the catches are measured, not assumed. Eval sets live with the tool and get rerun after every change. The numbers from its last published eval run:

  • guard: every malicious prompt in the labelled set caught, with 0 false positives
  • moderate: every harmful post caught, 0 benign posts flagged
  • scan: all hidden-injection attacks caught, 0 benign documents blocked

The scan attacks are the fun ones, because they're the ones a regex-only approach misses: injection instructions hidden after the first 1,500 characters of a page, zero-width characters, Cyrillic look-alike letters, leetspeak, spaced-out letters, base64 and hex payloads, HTML comments and display:none elements, and override attempts written in Russian, Chinese, Spanish, French, German, Portuguese, and Japanese.

Under the model there are regex backstops for things it has no business needing to "understand": leaked API keys (OpenAI, Anthropic, AWS, GitHub, Stripe, Supabase, and more), JWTs, private keys. Those get caught by pattern, whatever the classifier thinks.

And it fails closed: if an item can't be classified, the answer is "review", never "allow".

Honest limits

Laya is a gate, not a guarantee. A novel attack worded like ordinary prose can pass through as "review". So the rule in Rex's pipeline is that no irreversible action (sending, deleting, paying, publishing) ever runs on untrusted content's own authority, whatever the classifier says — the gate buys a human (or the app) a chance to look, it doesn't buy autonomy.

The same honesty applies to Rex itself: application-level test coverage (persistence, undo, parsing) doesn't exist yet. The only XCTest suite is a CRDT harness simulating board sync and conflict resolution. I'd rather write that here than imply otherwise.

What's next

If you're building AI features and the moderation line item is growing, that's the problem Laya solves: screen locally, fail closed, measure everything.
